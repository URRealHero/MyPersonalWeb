1 GPU & Triton Basics

1.1 GPU

Modern GPUs are throughput machines. You get speed by keeping thousands of lightweight threads busy and by streaming data through fast on-chip memory.

  • SMs (Streaming Multiprocessors): independent compute units that schedule warps and run your kernel.
  • Warps: groups of (typically) 32 threads executing the same instruction (SIMT). If threads branch, the warp serializes.
  • Memory hierarchy (fastest → slowest):
    • Registers (per-thread, tiny, fastest)
    • Shared memory / on-chip SRAM (per-block/program, fast)
    • L1/L2 caches (hardware-managed)
    • Global memory (HBM) (large, high latency; high bandwidth if accesses are coalesced)
  • Performance levers:
    • Tiling: load a small tile from global → compute heavily in registers/SRAM → write back.
    • Coalescing: threads in a warp should touch contiguous addresses.
    • Occupancy: keep enough warps resident to hide latency.
    • Arithmetic intensity: do more math per byte moved.

Think in tiles, not elements. A good kernel is “load tile → compute a lot → store tile”.
